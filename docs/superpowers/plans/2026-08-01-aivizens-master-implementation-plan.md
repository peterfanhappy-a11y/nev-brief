# AIVIZENS Production Launch Master Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Launch AIVIZENS as a production-ready, email-first AI daily publication and fully retire the legacy NEV product after verified backup.

**Architecture:** Preserve Hermes-to-Gmail as the launch input adapter, then pass normalized Digest data through quality gates, human approval, an immutable publication state, public daily archives, and idempotent Resend delivery. Decommission NEV only after AI dependencies have been neutralized and the production backup has passed a restore drill.

**Tech Stack:** Python 3.12+, Fast/strict pytest, psycopg 3, Pydantic 2, DeepSeek, Qwen VL, Gmail IMAP, Supabase/Postgres/Storage, Next.js 14, React 18, TypeScript, Vitest, Playwright, Resend, launchd, Vercel, Feishu webhooks.

## Global Constraints

- Production brand remains `AIVIZENS`; domain remains `https://aivizens.com`.
- Sender remains `AIVIZENS 趋势 <aivizens.daily@aivizens.com>`.
- Content generation runs at 06:45 Asia/Shanghai; approved publication and delivery run at 08:00 Asia/Shanghai.
- Human approval remains mandatory until the user explicitly authorizes automation.
- Launch input is Gmail Digest generated by Hermes; Markdown ingestion is out of scope.
- New subscriptions require double opt-in, server-side Turnstile, and durable rate limiting.
- Public content uses full daily archives at `/daily/YYYY-MM-DD`; no per-story pages in launch scope.
- Keep the current “100,000+ readers” and company-logo trust bar per the final user decision.
- Keep current `href="#"` social entries per the final user decision.
- NEV URLs return HTTP 410; they do not redirect.
- Back up and restore-test NEV data before its production deletion.
- Clear current AI subscribers before opening production subscriptions; preserve existing AI briefs, articles, and images.
- No production mutation occurs until the relevant phase gate and exact target verification pass.

## Cross-Phase Interfaces

- Phase 1 produces confirmed `ai_subscribers` rows with `status='active'`.
- Phase 2 produces public-read functions over `ai_daily_briefs.status='published'`.
- Phase 3 produces the `DigestInputAdapter`, quality report, brief workflow state machine, approval CLI, release CLI, stats CLI, and split launchd schedules.
- Phase 4 produces and deploys a single-product AIVIZENS cutover with signup/sending disabled, applies the validated schema, and completes independently verified NEV backup/data retirement.
- Phase 5 freezes the launch release, clears legacy AI subscribers, validates one controlled production address, installs schedules, and opens the subscription entrypoint.

## Master Acceptance Gate

Run from the repository root:

```bash
make verify
uv run python -m ai_brief stats --date "$(date +%F)"
curl -fsS https://aivizens.com/ >/dev/null
test "$(curl -sS -o /dev/null -w '%{http_code}' https://aivizens.com/nev)" = "410"
```

Expected:

- `make verify` exits 0.
- `stats` returns a structured summary without secrets.
- Homepage returns 200.
- `/nev` returns 410.
- A fresh email cannot enter delivery until confirmation.
- An unapproved or blocked brief cannot be published or delivered.
- Re-running release/delivery does not duplicate email.
