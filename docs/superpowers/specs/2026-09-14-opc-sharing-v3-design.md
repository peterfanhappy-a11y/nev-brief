# AIVIZENS OPC 分享 V3 日报设计

**日期：** 2026-09-14
**状态：** 已完成对话设计确认，等待书面 spec 审核
**适用范围：** 2026-09-15 起的新日报，以及一次性的 2026-09-14 受控回填

## 1. 背景与目标

当前 V2 日报由四类 Gmail digest 生成四个内容模块：今日AI、AI大神、AI研究、Agent工具。网页与邮件都读取 `ai_daily_briefs.content` 中的冻结内容，但还没有 OPC 案例数据源和栏目。

本次升级需要：

1. 从 `peter.fan.happy@gmail.com` 精确读取发件人为 `paul.fan.2200@gmail.com`、主题为 `ai-opc-sharing YYYY-MM-DD` 的当日邮件。
2. 解析邮件中的两个案例，将收入统一为美元月度营收，选择收入更高的案例。
3. 使用被选案例对应序号的图片附件，生成网页与邮件共用的 OPC 案例内容。
4. 将日报调整为“概览、OPC分享、今日精选、工具学习”四个部分和五个编号模块。
5. 网站阅读时长固定为 5 分钟，概览增加固定问候；网页与邮件共用更简洁、包含 OPC 推荐的编辑导语。
6. “今日 AI 简报”从三条扩展为四条，第四条来自 Agent工具第一条主题。
7. 任一 OPC 必需信息不完整时，严格阻止发布和发送。

## 3. 方案选择

采用 V3 冻结内容方案：OPC 在生成阶段完成采集、选择和图片上传，最终结果存入 `ai_daily_briefs.content`；网页和邮件只渲染冻结内容。

不采用以下方案：

- 复用 `featured`：字段无法清晰表达分享人、标准化收入与附件对应关系，且 V2 会清空该字段。
- 渲染时读取 Gmail：会令网页和邮件内容随外部状态变化，并让网站请求依赖 IMAP。

## 4. 输入契约

### 4.1 第五类 Digest

新增 `DigestKind = "opc"`，配置主题前缀 `ai-opc-sharing`。Gmail 适配器每天读取五类输入：

- `events`
- `builder`
- `opc`
- `research`
- `agent`

OPC 与 `events`、`builder` 一样只接受精确日期，不使用跨日期回退。IMAP 仍为只读，发件人继续使用现有 `AI_DIGEST_SENDER`，默认值为 `paul.fan.2200@gmail.com`。

### 4.2 实际邮件结构

已验证的 2026-09-14 邮件结构为：

```html
<h3>案例 1 · 分享人：案例主题</h3>
<p>案例正文</p>
<p><strong>收入：</strong>$83K+ MRR</p>
<p>🔗 <a href="https://...">...</a></p>
<hr>
```

邮件必须解析出恰好两个完整案例。每个中间候选包含：

- `index`：案例序号 1 或 2
- `sharer`：案例分享人
- `headline`：去掉“案例 N · 分享人：”后的主题
- `body`：案例正文
- `revenue_raw`：原始收入文本
- `currency`：原始币种
- `period`：MRR 或 ARR
- `amount`：原始数值
- `url`：HTTPS 原文链接

解析使用现有 `selectolax` 路线，不调用 LLM。正文、主题、分享人、收入和 URL 任一缺失都使该候选无效；最终不是恰好两个有效候选时阻断。

## 5. 收入标准化与案例选择

### 5.1 金额解析

支持带千位分隔符以及 `K`、`M`、`B` 的金额。`+` 只表示下限，不改变用于排序的数值。

币种优先读取 ISO 代码或明确币种文字，其次识别无歧义符号：

- `$`、`USD`、美元 → USD
- `€`、`EUR`、欧元 → EUR
- `£`、`GBP`、英镑 → GBP
- `CNY`、`RMB`、人民币 → CNY
- `JPY`、日元 → JPY
- 其他币种必须能映射到 ECB 返回的 ISO 代码

单独出现的 `¥` 或 `￥` 无法区分 CNY/JPY，按无法确认处理并阻断。

### 5.2 周期与汇率

- MRR/月度营收：保持月度金额。
- ARR/年度营收：除以 12。
- USD：不请求汇率服务。
- 非 USD：读取欧洲央行最新可用的工作日参考汇率，并通过 EUR 交叉汇率换算成 USD。
- ECB 报价为“每 1 EUR 对应多少目标货币”，因此 `USD = 原币金额 / 原币兑EUR报价 * USD兑EUR报价`；EUR 的原币报价视为 1。
- 周末或 TARGET 休市日使用最近一个已发布工作日的参考值。
- 请求设置有限超时；响应缺失、币种不支持、数值无效或换算失败时阻断发布。

ECB 官方参考页：<https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html>

### 5.3 选择与展示

比较两个候选的美元月度营收，选择较高者；完全相等时稳定选择案例 1。

- 原输入即 USD MRR：`收入：$167K 美元月度营收`
- 发生币种或 ARR 换算：`收入：约 $142K 美元月度营收`

最终数值使用适合阅读的 `$N`、`$NK`、`$NM` 或 `$NB` 格式，不显示 `MRR`。

## 6. 图片绑定与处理

被选案例 N 必须使用第 N 个案例图片：

1. 优先匹配文件名中明确的 `caseN` 或案例序号。
2. 无明确文件名时，仅在邮件恰好有两个有效图片附件的情况下按图片附件顺序匹配。
3. 不让 Qwen 从两个案例图片中重新选择，防止内容与图片错配。
4. 沿用今日AI的空白图、损坏图和透明图检测。
5. 沿用今日AI头图的裁剪、压缩、Supabase Storage 上传和公开 URL 生成流程。

选中图片不存在、不可解码、全空白或上传失败时阻断发布，不使用另一个案例的图片兜底。

## 7. V3 冻结内容契约

`AiBriefContent.version` 扩展为 `1 | 2 | 3`，新增可空字段 `opc_case`。V1/V2 允许其为空；V3 必须存在并通过质量门禁。

最终 OPC 对象使用独立结构，而不是把收入塞入普通 `DigestStory.label`：

```text
OpcCase
  sharer: string
  headline: string
  summary: string
  original_revenue: string
  monthly_revenue_usd: number
  revenue_display: string
  url: HTTPS string
  header_image: HTTPS string
  header_image_alt: string
```

`monthly_revenue_usd` 用于审计选择结果，`revenue_display` 是冻结后的用户可见文案。网页和邮件不重新计算收入或请求汇率。

V3 继续要求：

- `ai_engineering = null`
- `featured = []`
- `tools = []`
- `daily_tip = null`
- `quick_hits = []`
- `yesterday_top = null`

## 8. 概览生成规则

### 8.1 编辑导语

未来日报仍由今日AI模型生成简洁的 AI 新闻导语，但 prompt 要求只写前半段核心判断，限制长度，为 OPC 推荐留出空间。

代码确定性生成最终导语：

1. 如果模型结果含“与此同时，”，只保留其之前的内容。
2. 如果不含该短语，保留完整的简洁导语。
3. 追加：`今日给大家分享一个来自“{sharer}”的“{headline}”OPC案例。`
4. 在不截断 OPC 分享人或标题的前提下，对前半段进行句子边界裁剪，使最终内容不超过 schema 上限。

网页和邮件都读取这一份冻结后的 `editorial`。

### 8.2 问候与阅读时长

网站在主标题后显示并加粗固定问候：

> 早上好，AI科技爱好者们！以下是今天最值得关注的 AI 洞察，5 分钟带你看懂全局。

网站所有日报固定显示 `5 分钟阅读`，不再按正文长度动态变化。

HTML 与纯文本邮件保留现有的订阅者个性化问候；邮件当前已显示 5 分钟，不改变。

### 8.3 今日 AI 简报

V3 的 `intro_bullets` 必须恰好四条：

1. 今日AI模型生成的第 1 条
2. 今日AI模型生成的第 2 条
3. 今日AI模型生成的第 3 条
4. `🧰 {Agent工具第一条 headline}`

今日AI模型少于三条或 Agent工具没有第一条时阻断发布。

## 9. 网页与邮件版式

V3 的固定顺序为：

1. 概览
2. 黑色横条 `OPC分享`
3. 黑色边框卡片 `一、OPC案例`
4. 黑色横条 `今日精选`
5. 黑色边框卡片 `二、今日AI`
6. 黑色边框卡片 `三、AI大神`
7. 黑色横条 `工具学习`
8. 黑色边框卡片 `四、AI研究`
9. 黑色边框卡片 `五、Agent工具`

OPC 卡片内部依次显示：

1. 案例分享人
2. 头图
3. 案例主题
4. 案例正文
5. 收入文案
6. `阅读原文 →` 链接

字号、边框、留白、链接样式和图片宽度复用今日AI卡片的视觉规则。网站图片使用响应式宽度与固定展示比例；邮件使用安全的表格布局和全宽图片。纯文本邮件使用相同字段顺序。

V1/V2 仍按现有模块顺序和编号渲染，不伪造缺失的 OPC 栏目。

## 10. 严格质量门禁

V3 增加以下阻断条件：

- `opc` 精确日期邮件缺失、过期或来自错误日期。
- 不是恰好两个完整案例。
- 任一案例金额、币种或周期无法确认。
- 非美元汇率不可用或换算失败。
- 被选案例 URL 不是有效 HTTPS。
- 被选案例对应图片缺失、损坏、透明、空白或上传失败。
- `opc_case` 缺失或不完整。
- `intro_bullets` 不是恰好四条，或第四条不是 Agent工具第一条主题。
- 五个必需模块中任一个缺失。

质量报告新增结构化 issue code、`opc` 路径、OPC 解析数量、标准化收入与新鲜度指标。运行记录只保存安全元数据，不保存 Gmail 正文和附件内容。

2026-09-14 已发布且已有投递记录，不能走普通 `generate → approve → release`，也不能修改既有已发送 delivery。采用一次性受控操作：

2. 精确读取并解析五类当日邮件；由 OPC 邮件生成 `opc_case`，由现有 Agent工具第一条生成第四条概览。
3. 将现有 editorial 的“与此同时，”及其后内容替换为 OPC 推荐句，构造 V3 候选。
4. 在邮件发送关闭的情况下运行完整 schema、质量、网页、HTML 邮件和纯文本邮件验证。
5. 将当前生产内容、source run 和质量报告保存到本机临时备份，并记录旧内容哈希。
6. 在单个数据库事务中新增一条已完成的可审计回填 run，并且仅在日期、`published` 状态和旧内容哈希同时匹配时替换日报内容及关联安全元数据。
7. 保持原 `published_at` 和发布状态，不改写既有 `ai_deliveries`。
8. 验证生产网站 2026-09-14 页面后，确认 `gito.fan@163.com` 仍是 active 订阅者，使用其真实退订 token 渲染测试邮件。
9. 使用固定 idempotency key 通过 Resend 直接发送一封测试邮件；不向其他订阅者发送，不插入或重置历史 delivery。

正式代码不保留任意修改已发布日报的通用 CLI。一次性操作失败时，在数据库提交前停止；若提交后网站验证失败，则用保存的旧内容和哈希执行精确回滚。
