# AI 日报四模块与今日 AI 配额设计

**日期：** 2026-09-02  
**状态：** 待用户审核

## 目标

从本规格上线后的新日报开始，将 AIVIZENS AI 日报调整为四个正式模块：

1. 今日AI
2. AI大神
3. AI研究
4. Agent工具

今日AI 固定展示五条内容，其中三条海外、两条国内。AI工程不再出现在新日报。历史日报保持原内容和版式不变。

## 范围与非目标

范围包括 AI Brief 的 digest 选择、质量门禁、内容版本、网页渲染、邮件渲染和测试。

不在范围内：重写历史日报、删除 `ai_engineering` 的数据库 JSON 字段、改变邮件源、改变订阅或投递架构。

## 内容契约

新生成的 `AiBriefContent` 使用版本 `2`。其 digest 模块为 `today_ai`、`ai_masters`、`ai_research`、`agent_tools`；`ai_engineering` 保持为空。

版本 `1` 表示历史内容，继续允许并按现有结构渲染。这样不需数据库迁移，也不会因为新模板而改变历史文章。

## 今日AI选择规则

事件 digest 解析后的分类以“国内”开头的项目判为国内，其他有效事件项目判为海外。选择层在调用正文压缩模型前，确定五个输入项目：

- 海外 3 条；
- 国内 2 条；
- 按原有事件顺序保留每个地区内的优先级。

每条输出标签由代码写死为 `海外新闻` 或 `国内新闻`，不让模型生成或改写该标签。

如果某一地区不足目标数量，今日AI无法满足结构化约束，质量门禁必须阻断该期日报。阻断时不得审批、发布或发送邮件。

## AI工程退场与历史兼容

未来生成器不调用工程 digest 的内容生成，也不把 AI工程写入 v2 简报。v2 质量门禁不再要求工程模块或其输入邮件。

v1 的网页和邮件维持旧模块集合和标题，不删除 AI工程。v2 仅渲染四个正式模块。

## 展示规则

v2 网页文章和 HTML/纯文本邮件统一使用以下标题：

- `一、今日AI`
- `二、AI大神`
- `三、AI研究`
- `四、Agent工具`

v1 继续使用既有的无序号标题与 AI工程栏目。网页首页的模块摘要从发布内容导出，因此 v2 不会出现 AI工程。

## 流程与失败处理

`Gmail digest → parser → 配额选择 → 文本压缩 → quality gate → approve → release → deliver` 的现有顺序不变。

配额不足属于质量门禁失败，与其他阻断一致：生成记录为 `blocked`，不会创建发布内容或待发送投递。发送仍只在成功发布后显式开启。

## 测试与验收

新增或更新测试覆盖：

1. 五个事件含足量国内/海外时，v2 今日AI 恰有 3 条海外、2 条国内，且标签规范化。
2. 国内或海外不足时，质量门禁给出明确阻断，后续审批、发布和发送拒绝执行。
3. v2 内容不含 AI工程，并要求 AI大神、AI研究、Agent工具。
4. v1 网页与邮件仍显示旧标题和 AI工程；v2 只显示带序号的四个模块。
5. 网页、HTML 邮件、纯文本邮件和首页模块摘要使用同一 v2 标题与模块集合。

实施完成后运行完整 AI Brief 测试、网页相关测试、静态检查和禁发生成验证。通过后再提交、推送；后续首个正常定时任务作为生产验证。
