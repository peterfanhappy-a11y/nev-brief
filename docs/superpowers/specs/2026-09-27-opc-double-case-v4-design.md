# AIVIZENS OPC 双案例 V4 日报设计

## 背景

当前 V3 日报从主题为 `ai-opc-sharing YYYY-MM-DD` 的邮件中解析两个 OPC 候选，统一换算为美元月度营收后，只保留收入较高的一个案例。冻结内容、质量门禁、网站与邮件模板均以单个 `opc_case` 为接口。

从下一期开始，Hermes 邮件会为两个案例分别提供“案例背景、解决方案、案例启示”。日报需要保留两个案例，不再按收入筛选，并在网站和订阅邮件中按相同结构分段展示。历史 V1/V2/V3 日报不得被重写或因新契约失效。

## 目标

1. 精确解析 OPC 邮件中的两个案例并全部保留，展示顺序固定为案例 1、案例 2。
2. 每个案例必须包含分享者、主题、案例背景、解决方案、案例启示、收入、原文链接和对应头图。
3. 案例背景不超过 100 个 Unicode 字符，解决方案不超过 120 个，案例启示不超过 80 个。
4. 网站和 HTML/纯文本邮件使用同一份冻结内容和相同的信息顺序。
5. “今日 AI 简报”仍固定五条，第一条合并两个 OPC 案例主题。
6. 任一案例不完整时严格阻止发布和发送，并记录可定位到案例与字段的质量问题。
7. 历史 V1/V2/V3 内容继续按原格式渲染；新生成内容使用 V4，不回填历史日报。

## 非目标

- 不改变 OPC 邮件的发件人、主题匹配、精确日期和新鲜度规则。
- 不改变今日 AI、AI 大神、AI 研究、Agent 工具的选材和数量规则。
- 不回填或重写已有 V3 日报。
- 不改变收入换算来源与“美元月度营收”展示规则。
- 不在本次工作中调整自动任务时间、订阅流程或发送策略。

## 方案选择

采用新的 V4 冻结内容契约。

- 不修改 V3 的单案例语义，否则历史 V3 JSON 会被新校验拒绝。
- 不增加 `opc_case_2`，避免重复字段和位置语义扩散。
- V4 使用恰好两个元素的 `opc_cases` 数组，数组顺序就是邮件案例序号。

## 邮件输入契约

OPC 邮件继续要求：

- 发件人：现有 `AI_DIGEST_SENDER`。
- 主题：`ai-opc-sharing YYYY-MM-DD`，日期必须与日报日期完全一致。
- HTML 中恰好存在案例 1 和案例 2，每个序号只能出现一次。
- 两个图片附件必须能确定性绑定到对应案例；优先识别文件名中的案例序号，只有在没有任何序号且恰好有两张有效图片时才按附件顺序绑定。

每个案例块必须包含以下唯一字段：

```text
案例 N · 分享者：案例主题
案例背景：……
解决方案：……
案例启示：……
收入：……
阅读原文：https://……
```

解析时折叠多余空白，但不改写三段正文。缺字段、重复字段、空字段、重复案例序号、非 HTTPS 原文链接或无法解析的收入均视为无效输入。字符数按 Unicode code point 计算，与 Python Pydantic 和 TypeScript Zod 的现有跨语言边界规则保持一致。

## 数据契约

保留现有 `OpcCase` 和 `opc_case` 供 V3 历史内容使用。新增 V4 专用结构：

```text
OpcCaseV4
  sharer: 1..80
  headline: 1..120
  background: 1..100
  solution: 1..120
  insight: 1..80
  original_revenue: 1..80
  monthly_revenue_usd: positive integer
  revenue_display: 1..80
  url: HTTPS URL
  header_image: HTTPS URL
  header_image_alt: 1..160
```

`AiBriefContent` 调整为：

- `version: 1 | 2 | 3 | 4`。
- `opc_case`：V3 必须存在，V4 必须为空。
- `opc_cases`：V1/V2/V3 必须为空，V4 必须恰好两个。
- V4 与 V2/V3 一样禁止 AI 工程及所有退休的旧栏目字段。

Python 与 TypeScript 契约必须同时更新，并继续通过共享 Unicode 边界夹具验证。

## 生成流程

新增 `build_opc_cases`，替换新日报生成路径中的单案例 `build_opc_case`：

1. 解析恰好两个结构完整的候选。
2. 一次加载汇率，分别把两个收入换算为美元月度营收；ARR 仍除以 12。
3. 不比较收入、不排序、不删除案例。
4. 案例 1 只绑定附件 1，案例 2 只绑定附件 2；不得交叉替代图片。
5. 分别裁切、上传为稳定且不同的存储路径，例如 `opc-case-1`、`opc-case-2`。
6. 以案例序号顺序冻结为两个 `OpcCaseV4`。

任何解析、换算、图片绑定或上传失败都保留在现有持久化失败/质量阻断边界内，不进入发布与投递阶段。

## 概览与编辑导语

V4 “今日 AI 简报”仍严格为五条：

1. `💡 OPC案例：{案例1主题}；{案例2主题}`
2. 今日 AI 第 1 条
3. 今日 AI 第 2 条
4. 今日 AI 第 4 条
5. AI 大神第 1 条

编辑导语保留模型生成内容在“与此同时，”之前的核心判断，并追加固定短句：

```text
今日给大家分享两个 OPC 案例，详情见下方。
```

继续保持 220 字上限。先按句子边界裁剪前半段，不截断固定短句，也不把两个长标题塞入编辑导语。

## 网站展示

V4 页面顺序保持：概览 → OPC分享 → 今日精选 → 工具学习。

`OPC分享` 黑色横条下只保留一个编号模块 `一、OPC案例`。该模块使用一个黑色外边框，内部按顺序展示“案例 1”和“案例 2”，两者之间使用明确分隔线。每个案例展示顺序为：

1. 案例序号与分享者。
2. 对应头图，沿用当前完整宽度、自适应高度的展示规则。
3. 案例主题。
4. `案例背景：` 标签及独立正文段落。
5. `解决方案：` 标签及独立正文段落。
6. `案例启示：` 标签及独立正文段落。
7. 美元月度营收。
8. 阅读原文链接。

今日 AI、AI 大神、AI 研究、Agent 工具仍编号为二、三、四、五。V3 页面继续使用现有单案例组件。

## 邮件展示

HTML 邮件使用与网站相同的一个 OPC 模块、两个案例和字段顺序，继续使用兼容邮件客户端的表格布局与内联样式。两个案例之间加入边框分隔，不依赖 JavaScript 或现代 CSS。

纯文本邮件按以下结构重复两次：

```text
案例 1 · 分享者：……
主题：……
案例背景：……
解决方案：……
案例启示：……
收入：……
阅读原文：……
```

V3 邮件继续调用现有单案例模板，不改变历史重发结果。

## 首页与读取兼容

已发布日报仍从同一个 `ai_daily_briefs.content` JSON 读取。TypeScript schema、已发布日报详情和预览路由必须接受 V4。

首页摘要投影如需 OPC 标题，使用 V4 第一个案例标题并向后兼容 V3：

```text
COALESCE(content->'opc_cases'->0->>'headline', content->'opc_case'->>'headline')
```

首页卡片顺序、缓存刷新和 ISR 策略不变。

## 质量门禁与观测

V4 必须满足：

- OPC 原始候选数恰好为 2。
- 冻结 `opc_cases` 数量恰好为 2，索引顺序与邮件一致。
- 每个案例三段正文均非空并满足 100/120/80 字限制。
- 每个案例图片和原文链接均为 HTTPS。
- 每个原文链接必须能在受信任 OPC 邮件中找到。
- 每个案例月度营收必须为正整数并具有显示文本。
- 五条概览必须与两个 OPC 标题、今日 AI 1/2/4、AI 大神 1 完全一致。

问题路径必须能区分案例和字段，例如：

- `opc_cases[0].background`
- `opc_cases[0].header_image`
- `opc_cases[1].solution`
- `opc_cases[1].url`

运行指标保留 `opc_candidate_count` 和 `opc_case_count`；V4 的 `opc_case_count` 必须为 2。新增 `opc_monthly_revenue_usd_total`，值为两个案例美元月度营收之和，只用于观测，不参与排序或选取。字段长度或结构失败复用 `schema_invalid` 并携带具体索引路径；图片、URL 等已有问题继续复用现有 issue code。运行记录继续只保存安全元数据，不保存 Gmail 正文或附件内容。

## 测试策略

### Python

- 新 Hermes 格式夹具可解析两个案例及三段正文。
- 100/120/80 字边界分别验证通过与超限阻断，包括补充平面 Unicode 字符。
- 缺失、重复、空白三段字段及重复案例序号被拒绝。
- USD MRR、USD ARR 和非美元收入分别正确换算，两个案例均被保留。
- 两张附件严格按序号绑定、裁切和上传，不调用 Qwen、不交叉替代。
- V4 schema 只接受恰好两个完整案例；V3 单案例仍通过。
- 质量报告包含案例索引与具体字段路径。
- 五条概览和固定双案例导语完全匹配。
- HTML/纯文本邮件包含两个案例、六个分段正文标签、两张图片和两个原文链接。

### Web

- TypeScript schema 接受 V4 双案例并继续接受 V3。
- 网站只出现一个 `一、OPC案例` 模块，内部按顺序展示案例 1、案例 2。
- 两个案例分别显示对应图片、三段内容、收入和链接。
- V3 历史夹具仍保持单案例展示。
- 首页摘要读取 V4 时不会丢失或拒绝整期日报。

### 完整门禁

- `make verify`
- Python/TypeScript 契约边界测试
- 生产构建与 Vercel Preview
- 受控预览只验证内容，不发送订阅邮件；正式合并部署需要单独授权。

## 发布策略

1. 在独立分支以 TDD 实现 V4。
2. 通过完整门禁和独立代码审查后创建 PR。
3. 合并并同步 Mac Mini、部署 Vercel Production。
4. 不回填历史日报；下一次自动生成直接产出 V4。
5. 部署后检查自动任务日志和网站页面；仅在用户单独授权指定测试地址后才发送一封受控测试邮件，不得向全部订阅者补发历史内容。

## 验收标准

- 下一封符合新 Hermes 格式的 OPC 邮件可生成恰好两个案例。
- 网站和订阅邮件都按案例 1、案例 2 顺序展示三段结构化内容。
- 概览仍为五条，第一条同时包含两个 OPC 主题。
- 任一案例或字段异常时不发布、不发送，并能从质量报告定位原因。
- 历史 V3 日报的网页与重发模板保持兼容。
